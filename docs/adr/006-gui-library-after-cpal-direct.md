# GUI Library Choice for the cpal-direct Standalone

Owner: Z3U2

Last update: 20/05/2026

## Context

---

[ADR-003](003-gui-library.md) chose `vizia` for Tonism's GUI on the
strength of audio-specific widgets and concerns about egui's repaint
cost inside DAW plugin hosts. [ADR-004](004-gui-library-egui.md)
reversed that call to `egui`, primarily because `nih_plug_egui` was
co-maintained with the runner from [ADR-002](002-standalone-runner.md),
reducing single-maintainer hops in the load-bearing path.
[ADR-005](005-standalone-audio-cpal-direct.md) then dropped `nih-plug`
from the standalone path entirely, which removes the "co-maintained
adapter" argument that flipped ADR-003 → ADR-004. The cpal-direct
standalone has no GUI code yet (Phase D of the
[implementation spec](../specs/cpal-direct-standalone/spec.md));
this ADR decides which library Phase D builds on.

## Selection criteria

---

| #   | Criteria                                | Why this criteria ?                                                                                                                                                                                                                                                                                                                                                                                  |
| --- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Time to a working Phase D window        | Phase D's exit gate is "window opens next to a running audio stream, no GUI ↔ audio coupling, no underruns" ([spec.md](../specs/cpal-direct-standalone/spec.md#phase-d--window-stands-up-next-to-a-running-audio-stream)). Solo dev budget; bigger integration = bigger schedule slip. Includes the safety concern that the window event loop must not interfere with cpal-owned audio threads. |
| 2   | Audio-domain widget availability        | Tonism is a guitar processor. UI is fundamentally knobs + meters. A library that ships these is a near-term productivity win; one that doesn't forces hand-rolled widgets at the same cost regardless of which library we pick.                                                                                                                                                                  |
| 3   | Maintenance health and ecosystem size   | Solo OSS project ([strategic intent](../specs/product-architecture.md#strategic-intent)). The load-bearing dep needs long-term viability — community size, sponsorship, release cadence — to absorb upstream Rust / OS ecosystem churn without becoming a maintenance burden.                                                                                                                |
| 4   | Reusability for v0.2 plugin export      | [ADR-001](001-language-choice.md) keeps VST3/CLAP on the roadmap. When that path activates (Phase H or later), GUI code that survives the standalone → plugin transition saves a rebuild. [ADR-002](002-standalone-runner.md)'s "free reuse" was downgraded by [ADR-005](005-standalone-audio-cpal-direct.md) but not removed.                                                                  |

Criteria are numbered by priority (1 = most important). This order is
reflected in the Evaluation table columns.

## Recommendation

---

**Continue with `egui`** via `eframe` directly. It wins criteria 1, 3,
and 4: the existing [`editor.rs`](../../src/gui/editor.rs) closure
ports near 1:1 into `eframe`'s update closure (smallest Phase D
effort), Rerun sponsorship + 3-week release cadence beats the others
on maintenance health, and `nih_plug_egui` is the only in-tree GUI
adapter on the runner from [ADR-002](002-standalone-runner.md). The
accepted tradeoff is criterion 2: knob + meter are hand-rolled on top
of `param_slider`, the same one-evening cost
[ADR-003](003-gui-library.md) acknowledged. v0.2+ visual direction is
modern flat (ToneStack-style drag-and-drop signal chain) which is
squarely within egui's wheelhouse; the reversibility envelope (rule
A4) keeps the egui→vizia swap bounded to `src/gui/` + `Cargo.toml` if
that vision later shifts toward Skia-grade rendering.
